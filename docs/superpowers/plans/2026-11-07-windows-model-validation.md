# Windows 原生模型验证实施计划

**目标：** 在独立测试目录验证 RTX 5070 上 CosyVoice3 与 MuseTalk 1.5 的原生 Windows 加载、实际推理和显存占用，作为完整离线安装包的技术依据。

**方案：** 使用隔离的 Python 环境和固定模型源码，逐个验证模型，再验证同时运行；采集 GPU 空闲、加载后和推理期间的显存。生产配置、凭据和素材不作为安装包输入。

**技术栈：** Windows、Python、PyTorch CUDA、CosyVoice3、MuseTalk 1.5、FFmpeg。

**设计：** `docs/superpowers/specs/2026-11-07-windows-one-click-design.md`

## 全局约束

- 用户最终不需要安装开发工具或执行命令，交付须支持离线安装。
- 系统级依赖安装前先告知具体命令并取得授权；测试目录及 Python 虚拟环境独立于系统环境。
- 不将权重、运行素材、私有配置、真实地址和凭据写入 Git。
- 实测系统版本、驱动、显存与已有负载；Windows 11 结果不能替代 Windows 10 验证。
- 不操作线上服务，不对外推流；模型下载及分发前核对来源和许可。

## 验证步骤

1. 确认 GPU、驱动及可用磁盘，建立独立 Python 3.11 与 CUDA PyTorch 环境，执行实际 GPU 运算并记录结果。
2. 获取固定的 CosyVoice 源码、依赖及推理权重，处理 Windows 依赖冲突，执行一次真实语音生成；记录依赖版本、输出有效性、耗时及显存峰值。
3. 获取固定的 MuseTalk 源码、依赖与权重，使用有授权的样例图像及音频执行口型推理；记录输出有效性、耗时及显存峰值。
4. 两个模型同时驻留并运行，记录总显存峰值、吞吐及失败情况；如无法满足实时要求，明确原因并验证最小可行调整。
5. 固化可复现的版本和验证结果，作为 Windows 启动器、原生服务及安装器实施计划的输入；逐项检查资源许可及可离线分发性。

## 结果边界

CUDA 基础运算不代表模型已验证，单模型推理不代表双模型直播链路或空白机器安装已通过。每项只在实际执行并检查结果后标记通过。安装器、端到端直播和 Windows 10 验收属于后续工作，不由本计划的模型测试代替。

## 阶段记录（2026-11-07）

- 测试机系统实际为 Windows 11、NVIDIA 驱动 616.64、RTX 5070（12,227 MiB），测试前其他程序约占 1,768 MiB。Python 3.11.13、PyTorch 2.7.1 + CUDA 12.8 在隔离环境中完成 GPU 矩阵运算。
- CosyVoice 固定源码 `074ca6dc9e80a2f424f1f74b48bdd7d3fea531cc` 与 Matcha 源码 `dd9105b34bf2be2230f4aa1e4769fb586a3c824e`；通过官方模型镜像获取权重，并对照原模型版本的主要权重 SHA-256。
- 原生 Windows 单次生成成功：24 kHz、73,920 样本（3.08 秒）；模型加载约 11.43 秒，生成约 6.14 秒。加载后 PyTorch 分配 3,284 MiB，测试过程峰值分配 4,293 MiB、峰值保留 5,202 MiB。这些是单次样本和进程内指标，不等于整卡峰值、稳定性或实时性能。
- 测试采用上游示例参考声音，未人工听辨；ONNX 参考编码运行在 CPU。推理使用 PyTorch 2.7 的旧权重兼容选项，需在打包时审查权重来源与加载安全。启动输出包含注意力实现警告，需进一步验证音质和数值行为。
- MuseTalk 上游源码 `0a89dec45a0192b824e3cf4daf96c239440c5ed8` 的核心模型、VAE 和 Whisper 在独立环境加载；使用上游视频与音频，测试程序另用 OpenCV 简单裁脸后生成一张 256×256 测试帧。加载约 7.61 秒，单帧测试含音频特征处理约 19.51 秒；PyTorch 峰值分配 6,845 MiB、峰值保留 6,976 MiB。未人工检查结果，且此测试不含正式人脸预处理、回贴或完整视频，不能代表正式链路通过。
- 测试机恢复后，CosyVoice 完成一次语音生成并保持驻留，MuseTalk 核心随后生成一帧；`nvidia-smi` 每秒采样的整卡峰值为 11,599 MiB，设备总量 12,227 MiB，测试前已有约 527 MiB 占用。采样可能漏掉瞬时峰值，且 CosyVoice 在 MuseTalk 推理时处于等待状态，不是同时生成，也不代表完整直播稳定性。测试进程结束后整卡占用恢复到约 548 MiB。
- 两模型同时工作的单次样本：CosyVoice 连续合成短句期间，MuseTalk 核心完成一张示例帧，整卡每秒采样峰值 11,874 MiB / 12,227 MiB；MuseTalk 核心测试含音频特征约 15.14 秒，期间一段约 3.8 秒的 CosyVoice 音频生成耗时约 16.47 秒。两进程均输出成功结果，但显存余量小、存在明显变慢；单次样本不证明可长时间实时直播，也无法排除采样漏掉瞬时峰值。
- 分阶段测试表明 MuseTalk 的 PyTorch 分配峰值 6,845 MiB 发生在加载阶段；1.16 秒音频的单帧测试，重置峰值后推理分配峰值约 2,048 MiB。加载后释放未使用的缓存，保留显存约 2,522 MiB。先完成 MuseTalk 加载、清理缓存并使其等待，再启动 CosyVoice 的单次测试，整卡每秒采样峰值 8,656 MiB，CosyVoice 合成约 3.08 秒语音耗时 5.86 秒。此项并非同时推理，不能直接与不同负载下的 11,874 MiB 样本对比；优化设置下的同时推理、时延和稳定性仍需验证。
- 同样先加载 MuseTalk 并释放未使用缓存，再持续重复生成核心帧，同时加载 CosyVoice 并合成一次语音：整卡每秒采样峰值 8,753 MiB，约 3.08 秒语音生成耗时 7.67 秒。帧循环重复使用同一人脸裁剪和音频特征，不能代表真实连续口型、音画同步或端到端直播；模型加载和缓存调整尚未接入正式服务。
- 语音和口型 API 的本机默认地址、独立令牌及远程语音缓存隔离，在 Windows 隔离目录通过 15 项自动测试，使用模拟服务，不代表真实 GPU 模型 API 或云端代理已联调。
- Windows 隔离目录启动了真实 CosyVoice API（GPU 0），预热后验证无令牌请求被拒绝，携带测试令牌的请求成功返回完整 PCM 流；本次请求耗时约 4.84 秒，测试服务随后停止。结果不代表远程 HTTPS、口型服务或完整安装包已验证。
- 完整人脸处理、实时推流、长时间稳定性、离线安装和 Windows 10 均未验证。

## 安装与原生迁移待核对

- 当前 Worker 使用 `/dev/fd` 与 `pass_fds` 传递第二路音频，Windows 不能直接复用，需实现并验证可中断、可清理的双输入传输，包含音画同步和异常退出。
- 项目当前使用 SRS 5 与容器服务。SRS 上游现提供 Windows x64 支持，但其新版本兼容性、实际分发文件及许可尚未验证；不能将不同版本直接视作等价替换。
- 安装包需包含构建时校验过的运行时、权重及服务，测试中已存在的工具、Python 管理器和系统 PATH 均不构成目标机器前提。
- 在临时 Linux 容器使用 Go 1.26、`GOOS=windows GOARCH=amd64 CGO_ENABLED=0` 构建 `backend/cmd/api-admin` 成功，产物识别为 Windows x64 PE 程序；这只证明可交叉编译，尚未在 Windows 启动或连接基础服务。项目 Go 版本与正式构建环境仍需固定。
- 管理端在现有本地 Node/pnpm 环境使用 Vite 构建静态文件成功；这只是资源构建，未验证 Windows 网关路由、登录、直播页面或空白机器安装。

## 本机直播音视频输出

- 为 Windows 增加本机音频传输，保留现有视频 stdin 与 Linux/macOS 音频管道。首段音频先写、FFmpeg 尚未打开音频输入、队列满、进程退出和停止时都不能无限等待或泄漏进程。
- 使用真实 FFmpeg 把固定帧和音频写入本地文件，检查两个媒体流及持续时间；再在 Windows 测试机执行相同测试。不使用直播平台推流地址或真实观众数据。
- 音频传输通过后继续验证本机模型服务、人物素材、基础服务与管理界面的完整链路；不能用本地 FLV 测试代替完整开播验收。
- 当前已实现 Windows 回环音频通道，在 macOS 上强制该通道并使用真实 FFmpeg 验证了双媒体流、约 2 秒时长及非静音音频；还验证了空输入、进程提前退出及缓冲队列上限。POSIX 原通道的同类文件测试通过。Windows 实机验证未执行，尚不能称作 Windows 直播通过。
