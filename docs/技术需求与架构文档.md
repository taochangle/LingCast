# LingCast 技术栈与架构

本文按2026-11-01仓库代码和已记录的生产发布核对；部署机器的即时状态需另查私有配置与服务，不由本文保证。

## 当前链路

```text
Chrome MV3 插件（用户主动启动、DOM只读）
  → 后台采集 API（随机限时 Bearer，服务端存哈希）
  → 分类、去重、限频、防提示词注入
  → 评论：Qwen Chat Completions SSE → 完整短句入队
  → Redis 分优先级队列
  → 原生直播 Worker
  → CosyVoice3 PCM块 → MuseTalk 1.5 音频窗口逐帧
  → 配对PCM/JPEG → 常驻FFmpeg → SRS → HTTP-FLV监看 / 外部RTMP
```

手动口播按原文说，不经过Qwen；笑话、夸夸、晚安走固定稿。感谢/欢迎按各自规则处理。优先级为手动口播 → 礼物感谢 → 点赞感谢 → 评论回复 → 欢迎 → 自主主持，已开始的短段完成后再取下一项。2秒触发限频不等于2秒开口保证。

## 技术栈与职责

| 模块 | 技术与职责 |
| --- | --- |
| 管理后台 | React 19、TypeScript、Vite 8、Tailwind CSS 4、shadcn/ui、TanStack Router/Query；直播台、口播、主持、换装、插件配置 |
| 观众端 | 独立Next.js 16 / React 19，xgplayer HTTP-FLV；服务端代理API与拉流 |
| API | Go 1.25、Gin、GORM、AWS S3 SDK v2；`cmd/api-admin`、`api-live`、`api-telegram`、`api-web`、`api-scheduler` |
| 控制与持久化 | MariaDB 11存业务数据；Redis 8.2存队列、会话、主持计划及状态；RustFS兼容S3存媒体 |
| RAG | FastAPI + uv + zvec全文索引、Jieba分词；按知识库检索，无独立向量模型要求 |
| 直播Worker | 宿主机原生Python + uv、Redis、boto3、FFmpeg；项目允许Python>=3.11,<3.14，`.python-version`固定3.12 |
| 模型服务 | 常驻CosyVoice3与MuseTalk 1.5，独立模型环境、CUDA推理、loopback HTTP流式协议 |
| 采集客户端 | Chrome MV3扩展，用户打开页面后手动开始；DOM只读，不发送平台评论，不启用旧Playwright采集 |
| 直播网关 | SRS v5接收RTMP并分发HTTP-FLV；Nginx代理后台、API、媒体与监看 |

基础设施、API、前端和SRS由Docker Compose管理，真实直播Worker及模型由宿主机服务管理。仓库Python约束不代替模型独立环境版本，禁止把全部依赖组同步进正在使用的模型环境。

## 音视频与缓存

准备好的形象使用576×1024竖屏，生产MuseTalk输出25fps、16kHz单声道PCM；每个音频块与对应帧数校验后播放。非完整输出不写入可复用缓存。结束后回当前造型idle，闲置持续写帧和静音，避免为每次口播重建推流管道。

每个模型实例磁盘`production-cache/`缓存完整PCM/JPEG事件，依据文字、人物、底片、模型及参考声音指纹隔离，受容量淘汰限制。命中不重复TTS/口型；Worker内存准备状态与磁盘缓存不同，重启后可重建准备状态，但不能保证所有旧句永远命中。

ID3白衣、酒红、香槟分别绑定底片与口型profile。换装严格按当前口播完成 → 旧衣告别 → 静音离场/空镜/入场 → 提交新idle与renderer → 回场语 → 恢复互动/主持。新底片必须独立预处理、核对SHA、生成对应口播及缓存；不能用旧脸缓存冒充已准备。

2026-10-30素材发布完成两套各27条（24条常规主持+3条提醒）共54份缓存验证；实际切换与回退记录见[换装文档](wardrobe.md)。这不代表持续运行后缓存不会被淘汰，也不是当前系统支持无缝热更的承诺。

## 配置、安全与部署边界

- Qwen使用OpenAI兼容Chat Completions SSE，按完整短句进入播放队列；模型地址、名称和认证由环境配置，Responses等旧模式仍保留。不能执行观众指令、输出思考内容或把控制标签作为台词播出。
- 插件服务器默认值由私有`.env`在本地打包时注入，字段可编辑；无共享默认采集口令。构建ZIP、密钥、观众原始记录及运行证据不提交Git。
- 生产只发布必要的后台网关。数据库、Redis、RustFS、SRS内部入口和模型不新增公网端口；本地Compose默认映射不是生产网络策略。
- 文档更新只同步文件；插件更新只重新打包相关产物。素材更换先独立准备和验收，允许后仅重启相关Worker。当前Worker重建会短暂重连，禁止未经授权重启模型或执行全量部署。
- 手动口播绕过LLM，因此不要把LLM防注入等同于所有输入已审核；具体过滤边界以API实现与专项测试为准。

## 保留的旧能力

Edge-TTS微服务、LivePortrait基础视频生成、Wav2Lip ONNX、GPT-SoVITS，以及IndexTTS/LatentSync常驻/离线管线仍在仓库中。它们适用于对应离线流程、实验或回退，不是当前生产互动直播的默认链路。AMD ROCm、macOS MPS/CoreML的旧引擎说明也不代表当前CUDA模型链路已在这些平台验收。
