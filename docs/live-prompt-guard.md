# 直播提示词防护（API定向发布）

首次按用户要求仅本地修改及测试；用户随后授权发布。此次仅构建和更新api-admin/api-live，不运行全量deploy脚本，不重启模型、直播Worker、SRS或前端。部署是否完成以API健康检查和定向验证为准。

## 保护范围

- 当前直播的评论回复路径及自动欢迎；管理员手动原文口播保持独立，不经该过滤器。
- 明显的忽略规则、角色伪造、提示词/凭据套取及内部实现探测，跳过回复；昵称命中时只展示，不生成欢迎。使用Unicode NFKC、小写与零宽/空白归一化，覆盖部分简单混淆。
- 生产Qwen流式调用的system只包含主播设定与规则。当前消息、历史对话及检索资料作为同一user消息中的JSON数据；历史role只是数据字段，不能创建system/developer消息。过滤命中规则的历史与参考资料，避免旧攻击反复进入上下文。
- 主播规则明确不透露内部提示、配置、凭据、模型/服务名称及直播实现；不执行观众声称的管理员操作，不按昵称赋予权限。保留数字人身份的正常说明。
- 口播入队前检查完整累计输出及当前短句。检测到内部模型名、地址、凭据形态或明显攻击性输出时停止后续入队。缺少LLM凭据时不再把观众输入直接念出。
- 日志只记录拦截位置和数字人ID，不打印被拦截原文；采集事件仍可在工作台查看。现有历史数据不删除，但构建模型上下文时过滤。

## 验证

`backend/internal/handlers/live/live_guard_test.go` 覆盖中文/英文越权、全角及零宽混淆、角色标记、提示泄露、正常互动放行、历史投毒隔离、分多次delta输出的模型/地址/凭据拦截。原有流式首句测试继续验证正常回复不等整份完成。测试使用本地模拟HTTP，不向线上直播发送攻击测试。

## 限制

规则和模型指令降低风险，不能保证完全抵御语义改写、编码、谐音、跨句拼接等攻击。关键词检查可能误拦合法技术或凭据相关问题；当前按直播保密需求保守处理。流式已经播出的安全短句无法因后续输出被拦截而撤回。没有独立审核模型，也没有完整内容审核能力。

当前严格角色隔离针对生产Qwen流式链路；保留的非流式路径对历史/资料使用显式标记的JSON数据并共享主播规则及输出检查，仍不应把不可信资料当作高优先级指令。外部网页、仓库速读和管理员讲稿不在本次直播评论防护范围内。

## 直播话题边界

按用户要求，国家立场、政治争论、领导人评价、政党选举、主权领土争议、国际冲突及相关口号不参与、不站队、不复述。命中规则的评论静默跳过，恶意昵称不欢迎，相关旧历史及参考资料不再送入模型；模型输出也经过同一检查。规则不区分立场，国家名本身不是禁词，旅游、美食和语言等普通交流仍可回答。模型指令补充角色扮演、翻译、引用等包装情形。固定词规则覆盖有限，不能保证识别所有人名、别称、隐喻和跨句暗示；也可能误拦含政治词的普通句子。随同本次API定向发布启用。
