# 点赞/礼物感谢（0.1.3）

最初在直播期间完成本地修改和测试，用户随后授权提交推送并定向发布。仅更新api-admin、api-live、管理前端及直播Worker；模型、SRS和调度器保持运行。插件同步更新到0.1.3，原密钥和配置保留。

| 顺序 | 来源 | 队列 |
| --- | --- | --- |
| 1 | 手动口播/普通互动 | `live_queue:{id}` |
| 2 | 礼物感谢 | `live_gift_queue:{id}` |
| 3 | 点赞感谢 | `live_like_queue:{id}` |
| 4 | 采集评论的回复 | `live_external_queue:{id}` |

取下一任务时按顺序选择，已开始生成/播放的口播会完成，不硬中断。主持准备也让位于感谢队列。

## 采集与开关

插件0.1.3读取带昵称的结构化通知：“为主播点赞了”和“送出… xN”；跳过首屏历史，保留节点签名、服务端事件ID/内容签名去重、30秒过期和房间revision校验。普通聊天即使写“送出人气票 x1”也仍是评论。新增thanks开关默认false，需用户勾选「自动感谢点赞/礼物」并重新开始才口播；原欢迎、回复开关独立。

截图只能确认文案，不能确认全部平台DOM结构。已用本地结构化行单元样例验证，未接触当前Chrome直播页。实际兼容性需之后验证，无法识别的行不猜昵称或声称礼物到账。

## 话术、限频与安全

- 礼物：固定“谢谢昵称送来的人气票，感谢支持。”；人气票之外统称“礼物”。不念任意礼物描述、金额或数量，不作为支付证明。每房间最多2秒触发一次，同昵称/内容15秒内去重，队列上限3；突发会跳过，不承诺逐笔感谢。
- 点赞：固定“谢谢大家的点赞支持，看到你们啦。”。每房间最多15秒触发一次，队列上限1，连续点赞合并为通用感谢，不累计次数。
- 不调用Qwen生成感谢；昵称和通知文本沿用防注入/话题过滤。关闭开关时只展示，关播/停止/换房/撤销密钥清空新队列，旧revision不可播。

## 本地验证

插件Node测试覆盖通知样例、聊天不误报、主播排除、格式边界和协议。Go全量测试及隔离MariaDB/Redis测试覆盖默认关闭、独立入队、点赞合并、评论容量不受影响和关闭清理。Python测试覆盖六级顺序、旧房间感谢丢弃和现有播放/主持行为；前端构建通过。

本地测试未使用真实直播间，也未启用Playwright采集；DOM识别仍需实页观察验证。发布涉及插件、API、Worker和后台标签，旧服务端不接受新增事件类型，不可仅更新插件就启用感谢。
