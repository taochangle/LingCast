# 自主主持（2026-10-29 更新）

Live Studio「自主主持」支持输入话题和参考资料，调用现有 Qwen 生成短讲；也可以手写，每段空一行，1～12 段、每段 5～70 字。GitHub 项目速读可通过「用作自主主持资料」导入速读结论与固定提交号；仍只是部分文件分析。讲稿预览后才开始播放。

打开直播后点击「开始新一轮主持」。成都当前使用 CosyVoice + MuseTalk，提前准备分段的流式媒体缓存；旧 LatentSync 模式仍使用 IndexTTS + LatentSync 成品缓存。最多提前准备两段成品，当前段单独计数。段间随机停顿 10～25 秒（可设置 10～60 秒），本轮讲完停止。

调度顺序为手动口播 → 评论回复 → 欢迎 → 自主主持，评论和欢迎分别排队。正在播放的短段会讲完，已有模型请求也必须完成，不能承诺立即打断。新低优先级素材请求只在手动队列和手动配音空闲时发起；主持成品只在播放管线空闲时送入，一次一段。插话结束后继续下一段。

「暂停」保留预备素材；「继续」恢复；「结束」丢弃未播放的本地预备素材，不删除 RustFS 缓存。生成失败后等待明确重试。Redis `live_host:{avatar}` 保存计划和模式，`live_host_status:{avatar}` 保存进度。Worker 重启从未完成段落重新准备；重启前正在说的段落可能重播一次。刷新/关闭浏览器不会停止主持；关闭数字人直播停止执行，重新打开会按保存模式恢复。

接口均走管理员认证与现有 59480 网关：
- `POST /api/live/:avatarID/host/plan`：topic、material，返回 scripts。
- `GET /api/live/:avatarID/host`：计划与进度。
- `PUT /api/live/:avatarID/host`：action=start/pause/resume/stop；start 带 scripts、min_pause、max_pause。

小红书互动由用户手动启动 Chrome 插件采集，已验证真实进场欢迎和评论自动回复，见 [Chrome 插件采集](chrome-collector.md)。自主主持本身不会开启采集或向小红书评论框发送内容；采集到的评论回复优先于欢迎和后续主持段落。没有新增对外端口。

验证：Worker 主持优先级、暂停、恢复、重启、失败重试测试；Go 全量测试与真实 Redis 队列测试；管理端构建及新面板 ESLint。

## 欢迎与陪伴话术库（2026-10-28）

Live Studio 增加「准备话术库并循环主持」。首批 24 条，12 条欢迎、4 条自我介绍、4 条日常闲聊、4 条轻松互动，使用当前数字人姓名，不伪造弹幕或进场事件。管理员 PUT host action=start_library 使用服务端固定台词，不调用 Qwen；全部台词准备好之后才循环播放；当前 MuseTalk 模式准备流式缓存，旧 LatentSync 模式准备视频成品。已有媒体缓存会按台词、音色、底片和模型指纹复用。首次准备进度为 n/24，生成失败可暂停后继续重试。

播放阶段为预备素材保留独立副本。MuseTalk 模式使用缓存标记，请求常驻服务读取音视频事件缓存，命中时不重新运行模型；旧 LatentSync 模式直接播放本地成品。每轮分别打乱欢迎与其他话术、交替播放，一轮内不重复，段间停顿 2～4 秒；手动口播优先，暂停后继续保留预备素材。结束释放本地预备素材，模型媒体缓存保留。Worker 重启后重新从缓存准备，换底片需要重新开始，避免旧画面混播。旧的一轮讲稿功能保留。不会自动开启小红书采集或外部推流。
