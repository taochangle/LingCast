# 自主主持（2026-11-02 代码核对）

代码入口：`backend/internal/handlers/live/host.go`、`host_library.go`、`host_wardrobe.go`，`worker/ai/host_director.py`与`stream_worker.py`，前端`features/live-studio/host-panel.tsx`。

## 两种模式

| 模式 | 讲稿与播放 |
| --- | --- |
| 自定义一轮 | 1～12段，每段5～70字；可手写或用Qwen按话题/参考资料生成，预览后启动；最多预备两段，讲完本轮结束 |
| 欢迎与陪伴话术库 | 24条常规稿：12欢迎、4自我介绍、4闲聊、4互动；使用当前数字人姓名，不调用Qwen生成固定稿，循环主持 |

自定义讲稿停顿10～60秒，界面初始范围10～25秒；话术库固定2～4秒。ID3启用换装开关时追加3条换装提示，共27条。普通话术按已准备部分交替轮换，**首条普通话术准备好即能开讲**，其余后台串行补齐，不等待整库完成；准备进度反映实际已就绪条数。

主持使用当前造型的CosyVoice/MuseTalk流式媒体缓存标记，命中读取完整PCM/JPEG事件，不重复运行模型。磁盘缓存受容量与指纹规则约束，内存准备条数不是永不过期的命中承诺。

## 调度、暂停与恢复

取下一任务的顺序：手动口播 → 礼物感谢 → 点赞感谢 → 评论回复 → 欢迎 → 自主主持。感谢及其他互动排队时，不发起新的低优先级主持准备；已开始的模型请求或短段仍完成，不承诺立即打断。

暂停保留已准备片段；继续恢复；结束清理本地标记/片段，不主动删除模型磁盘缓存。生成失败后暂停再继续可明确重试。Redis `live_host:{avatar}`存计划与模式，`live_host_status:{avatar}`存进度。刷新浏览器不停止主持；关播停止执行，重新开播按保存模式恢复。Worker重建后重新准备，正在说的段落可能重播。

换装后销毁旧造型的主持准备状态，以新底片和renderer重建，首段就绪即恢复。任意更换底片不等于已完成新造型预处理，不能把其他造型缓存混播。

## 换装提醒

只在ID3固定话术库、API开关、完整manifest与renderer身份、插件采集及自动回复均满足时提示。首次至少4分钟且讲完3段普通主持，之后每4分钟至多一条且至少隔3段，三条轮换。提示本身不会自动换装，暂停/结束不播。旧任务需重新启动话术库才能获得新增提示。详见[换装](wardrobe.md)。

## 管理API

所有操作需要管理员会话，通过已有后台网关访问，不新增公网端口。

- `POST /api/live/:avatarID/host/plan`：话题及参考资料生成讲稿，尚不播放。
- `GET /api/live/:avatarID/host`：计划、状态及服务端话术库。
- `PUT /api/live/:avatarID/host`：`start` / `start_library` / `pause` / `resume` / `stop`；开始前必须已开播。

项目速读可导入部分仓库文件分析与固定提交号，不是完整代码审计。自主主持不会自行开启Chrome采集或外部推流。相关测试覆盖优先级、首段恢复、暂停/继续、重建、缓存和换装提醒时钟；实际直播延迟仍需独立测量。
